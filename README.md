# LumaBridge-Display

Plataforma open source em desenvolvimento para espelhamento, extensao real de area de trabalho na sessao grafica ativa e interacao remota entre dispositivos, com emissor virtual Windows 11 x64 (`LumaBridgeIddDriver` + `lumabridge-host`) e arquitetura multiplataforma planejada para Windows, Linux (Wayland/X11) e Android.

## Estado Atual do Projeto (`M0.6`)

- **M0 (Emissor Windows & Validacao Funcional):** **Funcionalmente aprovada** no commit funcional `6b297856` (`Benchmark30s` 30 s e `ProlongedStability` 180 s com `D3d11DxgiVSync`, transporte GPU compartilhado sem readback CPU e `NVENC H.264`), **integrada em `dev` remoto (`M0_INTEGRATED_IN_DEV = True`)** via [PR #37](https://github.com/Altaeir-13/LumaBridge-Display/pull/37) e **Merge commit `23a28046`** (preservando a arvore qualificada `7f1685f7`, o commit funcional `6b297856` e o head final da consolidacao `a9ad7e43`; historico local/revalidado `M0.4.1` com `157/157` C++, `71/71` PowerShell, `InfVerif 7/7` e `2/2` execucoes controladas `9/9` E2E aprovadas, preservando duas reprovacoes sinteticas `p99` anteriores da `M0.4`).
- **Governanca, licenciamento e criterio de encerramento da `M0` (`M0.6`):** Os entregaveis de governanca estabelecem [`LICENSE`](LICENSE) (`Apache-2.0` para o codigo proprio), [`NOTICE`](NOTICE), [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md), [`CONTRIBUTING.md`](CONTRIBUTING.md) (`DCO 1.1` prospectivo como declaracao de conformidade, nao autenticacao criptografica), [matriz real de testes](docs/setup/ci-and-test-matrix.md) (`164/237` casos historicos Windows ≈ `69,2%` do inventario no CI nao administrativo, sem classificar os `73` casos excluidos como reprovados, mais autotestes Python contabilizados separadamente) e os workflows iniciais em `.github/workflows/`. **Criterio objetivo de encerramento formal:** a `M0` permanece formalmente aberta ate a integracao do [PR #38](https://github.com/Altaeir-13/LumaBridge-Display/pull/38) em `dev` por Merge commit, aprovacao dos workflows pos-merge em `dev`, reconciliacao das pendencias documentadas (`PR #36`, `Issue #33` e `Issue #34` como escopo residual nao bloqueante) e verificacao da protecao de `refs/heads/dev`.
