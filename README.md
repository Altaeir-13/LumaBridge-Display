# LumaBridge-Display

Plataforma open source em desenvolvimento para espelhamento, extensao real de area de trabalho na sessao grafica ativa e interacao remota entre dispositivos, com emissor virtual Windows 11 x64 (`LumaBridgeIddDriver` + `lumabridge-host`) e arquitetura multiplataforma planejada para Windows, Linux (Wayland/X11) e Android.

## Estado Atual do Projeto (`M1.1` — PoC FFI em Revisão)

- **M0 (Emissor Windows, Governança e Encerramento Formal):** **Formalmente encerrada (`M0_FORMALLY_CLOSED = True`)** em `origin/dev` (`440ca3ab8889e4985d9a15862301f45a6cea762a`, integrando [PR #37](https://github.com/Altaeir-13/LumaBridge-Display/pull/37) em `23a28046` e [PR #38](https://github.com/Altaeir-13/LumaBridge-Display/pull/38) em `440ca3ab`, preservando o commit funcional `6b297856`, a árvore qualificada `7f1685f7`, checks Windows/Linux aprovados e proteção de `dev` via Ruleset `28020487`). Qualificação EV/WHQL de produção permanece em `M6`.
- **M1 (`M1.1` PoC Rust ↔ C++ MSVC 14.51, C ABI e Android/UniFFI):** **Iniciada pela subetapa `M1.1` (`M1_COMPLETE = False`)**. O workspace experimental isolado [`core/`](core/Cargo.toml) comprovou localmente todos os 5 critérios da [ADR-0004](docs/architecture/ADR-0004-core-language-and-native-boundaries.md) (builds MSVC `14.51` Debug `/MDd` e Release `/MD` com linkage opt-in em [`lumabridge-host.exe`](windows/host/main.cpp), overhead FFI `p99 = 51,0 µs` / pareado `35,5 µs` em 1.800 pacotes sintéticos @ 60 pps, `120` ciclos sem vazamento de handles, contenção de pânico `catch_unwind` e cross-build Android ARM64 + Kotlin UniFFI em [`core/android/README.md`](core/android/README.md)), registrados no relatório [m1-ffi-poc-report.md](docs/architecture/m1-ffi-poc-report.md). `ADR-0004` e `ADR-0005` permanecem em **`Proposed`** aguardando revisão formal do mantenedor. Escopo restante da `M1` (`LBWP v1` completo, pareamento SPAKE2/QR, mTLS, QUIC/TCP/TLS, mDNS e receptor Linux) ainda não foi iniciado.
